# 性能检查与优化 — 2026-11-10

本轮保留原有原生 Go/MyGo 界面、题库、复习算法、学习记录格式及画布完整性。所有基准与交互测试使用临时学习目录，没有写入实际学习文件。

## 已实施的修改

- 章节队列直接遍历唯一题库一次，取消“全量 ID 列表 + 去重表 + 二次列表”的逐帧分配。错题队列通过集合查询，只有新增到期成员才随机插入，已有顺序保持不变。
- 到期时间只读查询直接读取有效复习状态，取消无意义的 Review/权重数组复制。无效或空状态仍按原有新题的零到期时间处理，调度公式未变。
- 答题卡改用 MyGo 原生虚拟列表，仅构建可见行及少量预读行。每行仍为 6 格、32px 高、8px 间距，滚动视窗仍为 192px；题号、颜色和跳题映射不变。
- 富文本缓存有界：预处理字符串 256 条 / 2 MiB，公式 SVG 256 条 / 8 MiB（按原始数据估计），图片 32 张 / 96 MiB（按 RGBA 像素估计）。这些是缓存表的容量预算，不是整个应用 RSS 或 GPU 总内存上限；淘汰的内容按需重建，原始题目和笔记附件不删除。
- 平滑笔画几何写入一次预分配数组，不再为每个二次曲线创建临时切片和输出数组。

## 草稿专项第三轮：数位笔隔离与区域分块

实现：

- 原生画布显式启用 MyGo 捕获隔离：笔按下后，其他设备的 down/move/up 在修改光标、按钮和捕获前被拦截。普通 UI 未启用此行为；笔正常释放后鼠标仍可书写。真实系统取消继续传给控制器，保留原始片段。直接调用控制器也有同样的设备防护。
- 输入诊断只保留计数与 32 条异常时间：超过 80ms 的事件投递间隔、最大间隔、重复按下、捕获取消、其他设备拦截。没有坐标、题目或笔迹；设置中的“复制画布诊断”由用户显式导出，不自动落盘。投递间隔不等于硬件漏采样。
- 平移条带和局部擦除/移动修复使用世界坐标分块，内部 256px、边缘 2px，保持笔画叠加次序。LRU 表最多 124 块 / 32MiB RGBA 估算。实际后端纹理、当前视野及引用中的绘制资源不属于这个表预算；不应当解释成总 GPU 内存上限。
- 删除/恢复笔画时对齐未变的笔画头，只使真正受影响的块失效。倍率×DPR或主题变更会更换缓存集合。首次访问区域同步完成；旧的“停手才补齐”逻辑没有恢复。现有缩放预览及每帧八笔的分批重建保持不变，不积累多倍率大图。表淘汰不删除任何源笔迹；完整分块场景在纹理回收后可重放。

同后端 A/B：Apple M4 / Go 1.27.3 / 真实 Metal，480×320 画布，240 条、每条 40 点。交替移动到两个都偏离初始视野的位置，每帧跨越 overscan guard，预热两方向后测 20 帧。旧项重现已存在的空间索引条带矢量绘制，新项复用热分块；均包含构建、GPU 提交、等待完成和离屏像素读回。不是显示器呈现延迟，也没有数位板硬件输入。

| Metal 往返平移 | 索引条带矢量 | 热分块 |
|---|---:|---:|
| 平均 | 0.916 ms | 0.740 ms |
| P50 | 0.845 ms | 0.645 ms |
| P95 | 1.394 ms | 0.960 ms |
| 最大帧 | 2.181 ms | 1.894 ms |
| 每帧 Go 分配 | 674372 B / 961 次 | 640768 B / 179 次 |

这些是短跑方向性结果，不是统计置信区间或所有场景的加速承诺。首次访问需要完整绘制分块，未命中的稠密区域可能更贵。软件 Tester 会重新解释缓存绘制命令，原有软件 `BenchmarkFastPan` 未表现出加速，不能把它当成 Metal 纹理命中性能；其在初始视野和一个固定偏移间切换，也不能代表每帧都修复条带的负载。

验证：

- 原生事件路由测试混入鼠标移动/释放/按下，确认笔保持捕获、坐标不混入；正常笔释放后鼠标可用，真实取消仍保存片段。

## 2026-11-12：反向缩放与长笔画预算

- 缩放回最近完整底图的原始 camera 时，立即取消旧的部分重建和预览状态；旧任务不再留存为活动状态。
- 补边预览除 256 条笔画上限外，再限制为 1024 个样本/印章/擦除点的估计工作量；未生成印章的导入铅笔视为昂贵工作。少量长笔画不再绕过限流，在缩放的每一帧重复进行完整矢量补边。昂贵情况保持原完整视野，外侧先绘制纸面，停手后由原分批重建补齐。
- 清晰重建仍每帧最多八条可见笔画，另加 4096 工作单位的组预算，避免同一帧集中绘制多条长笔画。单条笔画保持原子绘制，以保留接缝最大覆盖及荧光笔叠色；极长的单笔仍可能成为慢帧，不声称严格 GPU 耗时上限。
- 新增反向缩放取消、少量长笔画预算检查，以及真实 Metal / 2× DPR 下反复打断缩放后对照完整矢量重绘。校验清晰底图不含重复叠色或旧任务残留。真实输入设备与窗口呈现延迟仍需实机体验。

## Device-separated transparent annotations

The app now draws cached paper, the interactive native question, then pen-only transparent ink. Ordinary writing reuses the paper viewport texture; camera/theme/size changes redraw it, and surface reset/close frees it. The navigation ink budget remains three working viewport targets, with the separate paper backdrop accounted for independently. No full stroke snapshot is introduced per pen event.

Software native-event integration checks show pen strokes on top of a question/option without selecting the answer, followed by mouse/trackpad option clicks, text drag selection, Cmd-C and explicit full-stem context copy. Original pressure/sample storage and question data remain untouched. Brightness tests now use pen input: mouse dragging on blank paper intentionally changes the camera, so paper dots/card shadows can move.

Transparent alpha requires replacing dirty pixels instead of painting transparent color over previous ink. Tests cover region-eraser feedback, committed masks, whole-stroke/tile deletion and ordered lasso layers. Transparent cached-run compositing may differ from a single pass by one 8-bit channel level in a small fraction of pixels; larger differences fail. The real Metal QA additionally covers transparent region erasure, deletion and pan versus complete reconstruction in both themes. Pen device isolation and pen-only hit selection remain opt-in to the native ink surface, and installed-source patch tests verify idempotence after gofmt.

## 2026-11-14 五项绘制路径改进

- 局部编辑：撤销/重做使用变更前后边界；像素擦除提交使用路径边界。取消整笔擦除/套索恢复受影响区域，单纯切换工具不失效底图。真正丢失纹理、尺寸/主题变化，以及缩放未完成就平移时仍保留完整恢复；其可见笔迹由空间索引查询，不再扫描所有原始点。
- 铅笔：`PencilStream` 保留随机状态和跨曲线间距，只生成稳定曲线的新增 stamps 和变化末端。抬笔消费尚未绘制的新样本；原始采样和 stamp 顺序不变。图集描述只解码一次，候选表使用固定栈数组。
- 索引：相机帧用 revision/count 快速复用；编辑继续对齐源笔迹，并增量删除/插入发生变化的网格单元。增删早期笔迹仍需更新发生位置变化的 ID，未宣称所有编辑都是 O(1)。
- 冷块：相邻一圈块在输入触发的有限后续帧里预生成，每帧至多 8 条 / 4096 工作单位；过大的原子笔画不参与投机预生成。未完成块不发布。可见冷块始终当前帧绘制，预算包含两个预生成目标，不使用周期保活。
- 复制：实时笔迹使用按 128 物理像素扩展的局部缓冲，扩展时迁移前缀而不重做几何。应用透明墨层的追加与渐进批次仅复制已占用区域；独立 demo 的不透明纸面仍保留完整复制，密集墨层也可能占满视口。没有宣称消除全部视口纹理。

显式诊断导出的 `render` 字段包含输入、画布 UI 构建、帧命令记录、底图准备、实时笔迹和分块同步 CPU 耗时；每阶段保留最近 32 次的 P50/P95 及累计最大值，并记录完整恢复、追加、复制像素、缓存命中与预生成数量。没有坐标、题目或自动文件日志。这些数值不包含 GPU 完成等待，也不是数位板到屏幕的端到端延迟。

Apple M4，`BenchmarkPencilGeneration`，160 个样本逐步增长，3 次短跑：同一新版采样器每帧完整生成约 786.6ms / 36.4MB，增量生成约 16.6ms / 0.55MB（整段 160 次更新合计，约 47 倍；不是单帧或 GPU 指标）。对照逐前缀 stamp 序列一致。

真实 Metal 现有 480×320 / 240×40 点夹具：两次短跑的热块平移均值约 0.68–0.86ms、P95 0.94–1.91ms，平移后落笔约 6.13–6.93ms。该短跑不能证明大窗口、冷块或数位板端到端改善；实际使用中的慢帧通过上述显式诊断定位。
