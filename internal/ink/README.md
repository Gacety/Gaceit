# Go + MyGo 原生笔迹引擎

基于用户提供的 `SPEC.md` 和四份原始 stroke GLSL 实现。原生演示单独放在 `cmd/ink-demo`，独立入口仍完整保留。主程序现通过 `internal/inkcanvas` 复用此渲染器与演示的原生输入/缓存逻辑，按用户设计绘制无限画布和学习面板；演示本身不依赖题库或学习文件。依赖当前项目的 MyGo v0.8.3，macOS 原生窗口由其 Metal 后端执行 Kage 着色器，不使用 WebGL。

```sh
# 从项目根目录运行
 go run ./cmd/ink-demo -demo
 go run ./cmd/ink-demo -tool pen -width 8
 go run ./cmd/ink-demo -tool highlighter -width 24
 go run ./cmd/ink-demo -tool pencil -width 10
 go test ./internal/ink ./cmd/ink-demo
# 无窗口导出检查图（MyGo CPU 解释器，不能代替 Metal 验收）
 go run ./cmd/ink-demo -render /tmp/ink.png -scale 2
```

## 接口

```go
renderer, err := ink.NewRenderer() // 初始化一次，并处理 err
stroke := ink.Stroke{
    Points: []ink.Point{{X: 30, Y: 40, Radius: 2}, {X: 70, Y: 10, Radius: 8}, {X: 110, Y: 50, Radius: 3}},
    Color: [4]float32{0.1, 0.2, 0.4, 1},
    Tool: ink.Pen,
    Smooth: true, // Points 来自鼠标/笔采样时启用；已有三点控制数据保持 false
}
// 在 MyGo Draw 回调里：
renderer.Draw(p, stroke, ink.Camera{Zoom: 1, PixelRatio: 2})
```

`Camera.Zoom` 将模型坐标转成 painter DIP；`PixelRatio` 必须是当前目标真实物理像素/DIP 比例，跨屏时更新。Camera.Offset 是 DIP 平移，Stroke.Translation 是模型平移。不要额外对 painter 施加缩放：通过 Camera 设置缩放，保证 AA 恰好为 1 物理像素。对离屏 Canvas 调用时 PixelRatio=1。颜色使用非预乘 sRGB，输出由着色器预乘。

## 六项对应

1. **点与半径**：`geometry.go` 使用滑动三点窗口，N 点生成 N−2 段；一/二点额外定义圆/中点控制的线段。位置和半径都二次插值，CPU 压力/速度函数 `Radius` 可选，几何输入已有半径时不再估算压力。
2. **四顶点与距离**：每段经 MyGo shader.Draw 输出一个原生四顶点 triangle strip。采用保守 AABB，包含三控制点凸包和最大半径，复杂大弧度不会被裁掉。归一化和 a/b/kk/kx 在 Go 侧每段预计算；片元解析解三次方程，计算最近点距离减对应半径。AA 为 `clamp(0.5 - sdfPixels, 0, 1)`，未启用 MSAA。距离使用 dst 物理坐标，避开 MyGo 矩形吸附造成的亚像素偏移。
3. **phase offset**：在原始着色器相同的 AABB 高度归一化空间计算；包络线方程 `dXY·(X−C)=−r·dr`，圆与直线两交点中点等于圆心在直线上的投影。无交点时使用向外的圆边缘，向内时丢弃。最近点的原始 t 保留到最终 `clamp((t+start)/(1+start+end),0,1)`。距离本身仍使用夹紧到 [0,1] 的 t。
4. **退化段**：模型阈值 0.05 和垂距/弦长 0.00005；端点圆互含时按较大端点圆处理；控制点贴近任意端点时改为端点三维中点。三次方程增加零除保护与 acos 输入夹紧，并比较所有三个根。
5. **荧光笔**：每笔独立 Canvas。每段以 backdrop 采样和不透明替换累积 `max(oldCoverage,newCoverage)`，部分 AA 边缘也不会叠加；最后乘算一次。跨笔叠色仍正常。每次 Draw 独立持有 mask，避免同帧相同尺寸笔迹覆盖彼此的 mask。普通笔也先取整笔最大覆盖率，再以正常 source-over 上色一次；修复相邻段重复混合 AA 边缘造成的加深和锯齿。正常上色的合成变体不读取页面 backdrop，覆盖率累积仍需读取 mask backdrop。
6. **铅笔**：真实 576 张图集和原始矩形表。`Stamp` 是 `[2][4]float32`，分别保存 `(x,y,opacity,angle)` 和 `(width,height,index,pad)`。MyGo 公共 API 不提供 RGBA32F 数据纹理，因此两个 float4 通过 Kage uniform 数组传入，保持布局与浮点精度；着色器用第一条的位置/角度和第二条的大小/索引对应矩形采样图集红通道，支持旋转、平移与负尺寸翻转。CPU 沿曲线近似弧长采样，按目标尺寸选择图集项，种子固定，重绘不闪变。显式设置 Stroke.Stamps 可直接使用已有印章序列。

## 验证与边界

`ink_test.go` 检查滑动窗口、两组阈值、圆互含、phase 投影、二次半径、DPR 1/2 的 1px 边缘、曲线解析距离与密集采样 oracle、同笔完整/部分覆盖率不叠色、跨笔乘算、透明底合成，以及真实图集的显式二 texel 印章读取。新增普通笔边缘重叠回归，以及 DPR 1/2、透明/不透明斜线的稀疏/密集采样一致性检查，确保增加采样点不会使边缘加深。自动像素测试使用 MyGo CPU 后端，验证数学和合成行为；不等于已在 Metal/Direct3D/OpenGL 上逐像素验证。

基础 `Renderer.Draw` 每段一个 draw、每次新建紧致包围盒 mask，适合一次性合成；普通笔和荧光笔每段的 mask backdrop 会产生额外捕获成本。原生演示使用下述 `LiveStroke` 前缀缓存与干墨双缓冲，避免活动帧全量重画。尚未做大规模笔迹或显示器端到端延迟验收。演示画布支持输入和压力，笔型、粗细、颜色和橡皮可通过原生浮动工具条选择，启动参数仍可设定初值；主程序已接入此引擎；仍不导入 `.goodnotes` 历史笔迹。铅笔 CPU 分布策略是自定的确定性实现，原应用的选章随机过程、压力拟合和视觉结果没有逐像素同一性保证。

来源与 IQ MIT 许可全文见 `THIRD_PARTY.md`；图集资产沿用用户给定的提取包。


## 快速拐弯的输入接段

原始 `Segments` 继续按规范解释滑动三点控制窗口。鼠标/触控笔的原始采样序列不是已整理的曲线控制数据；原生演示现在设置 `Stroke.Smooth=true`，用 `SampleCurves` 将采样点作为控制点，连接相邻采样的 x/y/radius 中点。接头共享同一端点，切线方向连续；内部二次曲线还具有相同的一阶导数。首尾补半段直线，保留真实输入起点、终点及圆头。单点和两点仍走圆/直线。铅笔 `MakeStrokeStamps` 也使用同一曲线链，避免干墨与湿墨路径不同。

这种输入平滑会将稀疏拐弯圆滑化，曲线不穿过每个原始采样点；它无法恢复输入设备未提供的轨迹。已有明确控制点的导入数据保持默认 `Smooth=false`，几何不会被自动改写。演示已取消按速度模拟宽度以及时间/空间压感滤波。数位板使用真实压力，鼠标固定等宽；输入设备规则见下文。

新增检查覆盖稀疏拐角的共享端点/切线、端点圆头、铅笔路径一致性、设备宽度规则、零压/原地压感变化、子像素位置和取消输入。自动截图对比及像素检查使用 CPU 渲染；本轮原生窗口检查限于可访问性控件树中的工具条控件，真实数位板手写效果仍需硬件确认。

## 输入延迟与缓存

原生演示的普通笔/荧光笔现在使用 `LiveStroke`：共享中点链中已经确定的前缀缓存为覆盖率纹理，只有新增的确定段和随最新采样改变的末尾半段需要绘制。逐次增加采样时，每帧通常提交 2 段；一帧积累多个采样则处理所有新增段。没有新输入时不重新生成几何。末尾直接到达最新输入坐标，没有位置低通、等下一点再显示或外推预测。不使用速度模拟或压感延时滤波。

已完成笔迹合成进双缓冲干墨 Canvas，仅在收笔时加入新笔。窗口尺寸、物理像素比例或 Camera 缩放/平移改变时重建视口缓存；显示比例查询只在窗口移动/缩放时更新，不在每次绘制时调用系统接口。缓存占用随视口物理像素面积增长，普通笔/荧光笔活动层使用 3 张覆盖率 Canvas，干墨使用 2 张 Canvas。覆盖率和跨笔合成规则保持不变。

`LiveStroke` 接收 append-only 的平滑采样，开始新笔或取消后调用 Reset；输入序列缩短、视口/Camera 改变时会重建。缓存正确性测试跨多帧比较完整重画的像素、验证最新笔尖位置、每帧提交段数以及干墨不随湿墨重建。铅笔活动层仍使用原印章绘制路径，尚未做印章增量缓存。上述提交量验证不是显示器端到端延迟测量，仍需原生手写体验确认。


## 数位板与鼠标

以 MyGo 在按下时上报的 Pointer 类型确定本笔设备，中途不切换：

- `PointerPen`：钢笔和铅笔使用真实 Pressure，圆珠笔与荧光笔保持等宽；铅笔不受普通笔的钢笔/圆珠笔子类型选择影响。不按移动速度改变宽度，也不把零压力替换为 0.5。启用压力的半径为 `width/2 × (0.2 + 0.8 × clamp(pressure,0,1))`，最大压力对应所选标称宽度。压感曲线目前是明确的线性映射，未做具体数位板的硬件标定。
- 鼠标/触控板及其他非 pen 输入：遵循工具条或启动参数明确选择的普通笔、荧光笔、铅笔，半径固定为 `width/2`，不受压力、速度影响；不会强制改回基础笔。
- 原地压力变化和子像素移动都即时记录，只丢弃位置、半径完全相同的重复点。抬笔事件的零压力不伪造突然收尖，但保留其最终位置。轨迹继续使用连续曲线与最新输入端点，不添加位置低通或预测。

自动测试验证事件处理规则，尚未对用户数位板驱动实际发出的 Pointer/Pressure 做实机验证。驱动若仅上报 mouse，程序会按鼠标规则等宽绘制。


## 原生浮动工具条

工具条属于独立的 `cmd/ink-demo` 原生演示，沿用暖纸画布；与 `internal/nativeapp` 的题库草稿纸保持独立。工具条使用固定屏幕尺寸：展开为 582×52 DIP，收纳为 68×52 DIP，不随画布缩放。启动时以细长横向图标条停靠右侧、距顶部 24 DIP。拖动最左侧握柄可自由移动，松手时距左/右边缘 32 DIP 内吸附到对应侧、保留 8 DIP 边距；吸附后仍保持横条结构。取消拖动恢复原位置和停靠侧。悬停图标可查看中文提示。

- 工具依次为普通笔、荧光笔、铅笔、橡皮擦、移动画布。动作图标使用 [Phosphor Icons](https://github.com/phosphor-icons/core) Regular 官方未修改 SVG（MIT），以 22 DIP 绘制。普通笔、荧光笔、铅笔、统一橡皮擦分别映射 `pen-nib`、`highlighter`、`pencil-simple`、`eraser`；`selection-slash` SVG 仍保留于 vendored 资产，但不再作为独立工具条动作。移动、设置、撤销、收纳、展开分别使用 `hand-palm`、`sliders-horizontal`、`arrow-u-up-left`、`sidebar-simple`、`pencil-circle`，下拉箭头和握柄也来自同一图标族。中文提示标签保持原语义。点普通笔图标会打开/收起设置，可选择钢笔或圆珠笔；粗细设置图标也能打开当前工具的设置，面板有「收起」按钮。钢笔与圆珠笔共用普通笔渲染，区别在于数位板压力宽度规则。
- 绘画快捷宽度为 2、4、8，设置面板滑杆范围 0.5–32、步长 0.5；橡皮快捷宽度为 8、16、32，滑杆范围 4–80、步长 0.5。值为画布世界坐标中的标称直径，100% 时对应 DIP，屏幕直径随画布缩放。所有绘画工具共享绘画宽度，两种擦除模式共享橡皮宽度。
- 色点为墨黑、朱红、天蓝。荧光笔在墨黑色点下使用黄色，在朱红/天蓝下使用相应颜色，透明度为 0.45；同一笔自交不加深，跨笔仍叠色。颜色选择不把橡皮切回绘画工具。
- 「橡皮擦」为带下拉箭头的单一入口，点击选择橡皮并打开设置；面板以「整笔擦除 / 区域擦除」切换模式，保留上次选择，不因重新选中橡皮而重置。
- 区域擦除：将路径记录在命中笔迹的 `Stroke.Erasures` 中，以透明覆盖率遮罩裁掉局部，保留原始点/印章，不用纸色覆盖。因此可露出底层，后写笔迹也不会被旧擦除遮罩擦掉。普通笔、荧光笔和铅笔均支持；这是非破坏性遮罩，并非重采样/切断原曲线。
- 整笔擦除：删除命中的整条原始笔迹，采用每手势复用的自适应曲线命中索引，铅笔印章采用包围范围；不等于逐像素可见颜色命中。两种擦除模式移动时均显示当前直径圆圈。
- 撤销按钮保存最近 50 次有效绘画/擦除手势，一次连续擦除只占一步；空擦不计入。绘画或擦除进行中禁用撤销。取消绘画不提交当前笔；取消擦除恢复手势开始前的笔迹及遮罩。暂无重做或会话持久化。

- 最右侧「收纳工具栏」隐藏展开条及设置面板，保留带握柄和「展开工具栏」按钮的胶囊；收纳状态仍能拖动和左右吸附。展开时恢复工具条，保留工具选择。

## 无限画布与导航

画布不设置固定世界边界，可向任意方向平移并在负坐标书写；实际范围仍受浮点精度与内存限制。演示用 `float64` 保存屏幕 DIP 平移量，世界笔迹/擦除路径及渲染 `Camera` 几何使用 `float32`，远距离移动并不保证无限精度。书写与擦除事件先反变换到世界坐标，导航不会改写既有笔迹或产生新笔迹。绘画/擦除手势进行中阻止相机导航，拖动平移取消时恢复手势前的位置。

- 鼠标滚轮缩放，范围 10%–800%，以指针下的世界点为锚；触控板精确双指滚动平移，按 Ctrl 或 Command 的精确滚动也走缩放。捏合手势以事件中心缩放。
- 空格加主键拖动、中键拖动或选择手掌「移动画布」后主键拖动均可平移；再选绘画工具或橡皮会退出手掌模式。
- 左下角依次提供缩小、当前百分比、放大、回到原点。加减按 1.25 倍调整，以视口中心为锚；点击百分比恢复 100%，保留中心锚点；回到原点同时恢复 100% 和零平移。工具条及底部控件保持屏幕尺寸。

缩放、DPR 或窗口尺寸改变时重建视口干墨缓存；纯平移使用下述带边界缓冲的快取。演示剔除屏外笔迹，并使用 `Renderer.DrawViewport` 将临时覆盖率/擦除遮罩限制在视口内，避免长笔迹或远处世界坐标产生巨幅离屏纹理。该接口的 `width`/`height` 与 painter 的 DIP 坐标一致；演示向物理像素 Canvas 绘制时传入对应像素 Camera 和尺寸。这是视口缓存及遮罩裁剪，并非分块缓存；导航重建仍会扫描笔迹，尚无海量笔迹性能保证。

图标固定来自提交 `2b75f3ad12b420c9504ef05df8d2564a28f8500e`，本地存放于 `cmd/ink-demo/assets/phosphor`。其中 `SOURCE.json` 记录逐文件上游 URL 与 SHA-256，`LICENSE` 保留 MIT 授权全文；归属说明见 [THIRD_PARTY.md](THIRD_PARTY.md)。`icons.go` 将 SVG 嵌入二进制、首次使用时统一解析一次，并通过原生 `ui.Painter.Icon` 绘制，无运行时网络或 JavaScript 依赖。

## 区域橡皮拖动优化

区域橡皮不再在每个输入事件中修改所有命中笔迹、令干墨失效。移动阶段只追加真实输入点；`ErasePreview` 用两张固定视口大小的覆盖率 Canvas 累积新扫过的线段，每帧只处理新增段，已累计的遮罩和干墨页面保留。输入点不会被降频丢弃；多个事件在同一显示帧中一起消费。拖动预览在缓存的整页上反馈擦除，使用纸色与页面的覆盖率合成；这只是预览，持久结果仍为每笔透明度遮罩，并非纸色笔迹。

抬笔时才进行一次命中记录提交，先按保守包围盒剔除无关笔迹，再为命中的笔迹追加一条擦除路径、重建一次干墨。取消区域擦除直接丢弃预览，原始笔迹和页面缓存始终未改动。撤销仍以整个手势为一步。整笔擦除的命中和干墨修复使用下节所述独立优化路径。

预览按整页合成，最终按每笔透明度遮罩提交；重叠半透明笔迹的部分覆盖率边缘可能有细微差别。完整擦除区和未触碰区保持一致。大页面在抬笔提交或调整视口时仍可能有一次重建开销；本轮主要消除了持续拖动时反复全页重建，并未声称所有工作量与笔迹数量无关。

新增测试验证拖动不使干墨失效、不修改持久笔迹、每新增一点只提交一段遮罩、合帧不漏点、取消直接复用页面、提交/撤销及 DPR 1/2 的 1px AA。`BenchmarkPixelEraserFrames` 在同一 CPU 渲染场景比较旧式整页重建与增量预览：Apple M4，160×120 DIP、DPR 1、60 笔×40 个采样点，8 帧，约 254.7ms/帧 → 6.76ms/帧（约 38 倍）。这是 MyGo CPU 后端对照，不是 Metal 或显示器端到端延迟测量。

```sh
go test ./cmd/ink-demo -run '^$' -bench BenchmarkPixelEraserFrames -benchtime=8x -count=1
```


## 整笔擦除拖动优化

整笔擦除的指针事件只追加真实采样点；`processStrokeErase` 在绘制帧和最终抬笔时消费所有新增点，合帧不丢点。每个手势首次处理时构建一次 `HitIndex`，自适应展平曲线并按 128 模型单位网格索引，按扫过范围筛选候选，跳过已经删除的笔迹，不再随每个指针事件反复重采样整场景。

删除后将笔迹的可见联合包围区域标为待修复：`dirty.go` 复用已有干墨双缓冲纹理，复制保留其他像素，在裁剪区域恢复纸色，并按原顺序用 `Renderer.DrawRegion` 重画与其相交的存活笔迹。普通笔、荧光笔和铅笔的遮罩同样限制在修复区域。持续拖动不再逐事件触发整页失效；整个手势仍只占一次撤销，取消时恢复手势前的完整笔迹状态并重建一次干墨。

`hit_index_test.go` 检查远处分布的 1,000 条笔迹仅筛出少量候选（测试断言少于 10），另有 DPR 1/2、缩放 1/1.7 下的重叠笔迹、铅笔、荧光笔像素对照，以及纹理/索引复用、两种 UI 模式与撤销检查。本轮查看 `.impeccable/review/ink-unified-eraser-{region,stroke}.png` 的区域/整笔设置截图，工具条和较窄窗口截图也已重新生成；这些仍是 CPU 渲染证据。

`BenchmarkStrokeEraserFrames` 在同一 CPU 场景对照旧式整页重建和索引/区域修复：Apple M4，160×120 DIP、DPR 1、60 笔×40 个采样点，8 帧，约 24.73ms/帧 → 1.657ms/帧（约 15 倍）。这是 MyGo CPU 后端结果，不是 GPU 或显示器端到端延迟。每个手势的一次索引构建仍随场景规模增长；修复仍扫描存活笔迹的包围范围，删除笔迹的联合范围很大时仍可能接近全视口重画。这不是分块缓存，也不保证任意场景下恒定耗时。区域擦除继续使用前节的增量预览及抬笔提交逻辑。

```sh
go test ./cmd/ink-demo -run '^$' -bench BenchmarkStrokeEraserFrames -benchtime=8x -count=1
```


## 画布平移快取

纯平移不再因 Camera.Offset 改变而逐帧重建全部可见笔迹。`pan_cache.go` 以现有干墨页面为中心建立两张带 192 物理像素外扩边界的固定大小 Canvas；缓冲区内的移动只改变贴图显示位置。靠近缓冲边缘时按整数物理像素搬移旧内容，只补画新露出的横向/纵向条带；条带互不重叠，避免荧光笔在角落重复叠色。极大跳转才重画整个缓冲范围。

用于条带筛选的笔迹包围盒与未预生成的铅笔印章在快取建立时准备一次。分数像素位移只在最终显示时应用，不反复烘焙回图片，减少连续平移造成的累积模糊。快取大小取决于视口，不随世界坐标范围增长。滚动式双指平移和手形/空格/中键拖动共用这一条路径。

开始书写或擦除时恢复与当前视口对齐的干墨页面；新增、删除、区域遮罩更改及撤销会使平移快取失效。缩放、窗口大小、DPR 改变仍需要重建；这是双缓冲视口快取，并非全世界分块快取。首次进入平移或跨越边界仍有建立/条带补画开销。

本轮依用户要求未运行测试、基准或截图验收，只进行代码修改、格式化与编译。上文已有测试与基准属于先前轮次，不能作为本次平移快取效果的实测依据。

## 套索选择与移动

工具条的 Phosphor 套索按钮进入自由框选。按住主键画虚线闭合轮廓，抬笔自动闭合；圈内或轮廓穿过的整条笔迹被选中。框选只在抬笔时复用自适应曲线弦进行几何判定，不在每次输入事件扫描场景。虚线及选中框维持屏幕尺寸，跟随画布缩放和平移定位。

在选中框内按住拖动可移动整组选中笔迹；框外重新圈选，单击空白可取消，Esc 取消选择或还原本次拖动。一次完成的移动对应一次撤销。移动通过 Translation 保留原始采样点和铅笔印章，并复制平移区域擦除路径，避免擦除孔洞留在原处；保持笔画顺序与荧光笔合成方式。拖动输入合并至每个绘制帧，沿用干墨快取的旧/新范围局部修复；范围很大的选择仍可能接近全视口重画。

本次套索功能依用户要求只做格式化和编译，未运行测试或交互验收。

快捷键 P 切换到上次使用的笔触，E 切换到橡皮擦；当前已是对应工具时再按同一键，返回上一次工具状态，包括套索或手形工具。工具条点击也更新切换记录，笔触与橡皮的子类型、粗细、颜色保留；没有切换记录时以笔/橡皮互换。快捷键使用 MyGo 窗口级 Shortcut，忽略长按自动重复及带修饰键的组合；书写、擦除、套索拖动或平移过程中不切换工具。本次仅编译，未运行测试。

## 主程序接入（2026-11-09）

`internal/inkcanvas` 是从演示控制器适配出的原生可嵌入组件，直接调用本包 Renderer/LiveStroke，复用采样、压感、擦除、套索、视口干墨与平移快取；`cmd/ink-demo` 的源码和独立入口保持原样。`internal/nativeapp/canvas_ui.go` 用 MyGo `ui` 绘制用户设计中的浮动题目、进度面板、笔记卡和工具栏。HTML 不参与运行。

主程序的默认中性墨色按主题显示为白/黑，独立演示仍使用原配色。暗色纸上的荧光笔沿用最大覆盖率几何，以半透明 source-over 保持可见；浅色纸沿用乘算。绘画、区域/整笔擦除、套索移动与撤销/重做由组件处理。相机、原始笔迹及矢量笔记片段由主程序随题持久化；旧归一化草稿字段保留。独立演示继续保持其原有的非持久化会话行为。
